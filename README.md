# 环形的心 · Ringmind

**v1.3.1**

一个**会遗忘**的记忆库。

给 AI 角色用的记忆系统：**她决定记什么，库决定什么时候忘。**

---

## 怎么装

**要 Node.js 22.5 以上**（用了内置的 `node:sqlite`，不需要装任何依赖）。

```bash
git clone https://github.com/ya-shua/ringmind.git
cd ringmind
node src/web/server.js
```

Windows 上直接双击 **`启动面板.bat`** 也行；想让它缩在后台不占窗口，双击 **`后台启动.vbs`**。

第一次启动会在窗口里打印一串**访问令牌**，同时写进 `data/token.txt`。浏览器打开 <http://127.0.0.1:5173>，用这串令牌登录就行。

> 令牌只在第一次生成。忘了就去看 `data/token.txt`。

## 更新

面板**左下角**发现新版本会自己冒出一个框，点「更新」就行——它会拉最新代码、自动重启，然后页面自己刷新。

**记忆库、设置、令牌、OneBot 配置都不会动。** 这些东西不在代码里：
`data/`、`libraries.json`、`data-location.json`、`onebot.json` 全在 `.gitignore` 里，更新只换程序。

你要是改过代码，更新前它会先把你改动收进 `git stash`，不会硬盖掉。

git 协议被墙时自动改走 GitHub 源码包（只覆盖仓库跟踪的文件），版本号识别也一样准——更新完不会一直提示有新版本。

不想用面板更新就手动来：

```bash
git pull
```

然后重启面板。

## 为什么做这个

现在的 AI 记忆都是"数据库"：存进去，永远读得出来。

**那不是记忆，那是档案。**

人会忘。忘得越久越模糊，被提醒能想起来一些，**但想不全**。

> "被提醒了也想不全"——这才是人。

所以这套东西的核心不是"存得住"，是**"忘得像"**。

## 一条记忆的一生

```
① 发生    她决定：记不记？多重要？放哪一圈？哪些点最要紧？
     ↓
② 安家    进她自己选的那一圈
     ↓
③ 活着    被人提起 → 自动往回拉一点（无意识，她管不了）
     ↓
④ 淡去    时间到 或 那一圈满了 → 往外掉一圈，同时删掉一部分"点"
     ↓
⑤ 模糊    只剩钩子，提一句还能"啊对对对"
     ↓
⑥ 尽头    钩子也丢了 = 真的忘了
```

**关键：她有权选择记住什么，但无权决定忘记什么。**

## 九个位置

| 位置 | 装什么 | 停留 | 可配 |
|---|---|---|---|
| 数据总库 | 原始存档，**她访问不到** | 永久（可设条数） | ✅ |
| 自我圈（圆心） | 她自己钉住的秘密/底线/承诺 | 永不外出（上限 300） | ✅ |
| 一圈 | 极其强烈 | 180 天 | ✅ |
| 二圈 | 很开心 / 很难过 | 60 天 | ✅ |
| 三圈 | 有点意思 | 14 天 | ✅ |
| **闲聊圈（四圈）** | 日常 | 5 天（第 1 天 100%，每天 -5%，待满 80%） | ✅ |
| **模糊圈（五圈）** | 开始糊了 | 30 天（一进去就是 40%） | ✅ |
| 回忆圈 | 只剩 30% 的随机点，想不起来 | 一年后彻底消失 | ✅ |
| 缓冲圈 | 闲聊圈、模糊圈的备份，唯一能"想起来"的通道 | 跟主圈同步 | ✅ |

**她自己只知道四个位置**：自我圈（圆心）、一圈、二圈、三圈。

**闲聊圈（四圈）是接盘层**：她没表态、没记的事都自动落进那里（5 天逐日淡）——她不知道有这一格，也就不会去管理它。**模糊圈和回忆圈更不会告诉她**，那两个是她掉进去才会撞见的；她也不会发现自己掉进去了，只会觉得"这事我想不太起来了"。

**百分比全部以「原文」为标尺**，不是叠乘。

> 上表的停留天数是**没选预设时的兜底值**。实际用预设：一圈 90 天、二圈 30 天、三圈 10 天（三档预设的圈一二三都一样，差别在闲聊/模糊/回忆圈的容量）。

### 怎么说这些位置

**名字在前，圈号在后。** 说「闲聊圈（四圈）」，不要只说"圈四"，也不要只说"闲聊圈"。

**一圈、二圈、三圈不起别名** —— 数字本身就是顺序，叫"长久圈""近事圈"那种反而跟实际天数打架（模糊圈 30 天其实比闲聊圈 5 天长）。

**光给她一个整句、她自己没拆点的时候，库会按标点替她切。** 一个字都不改，也不替她总结 —— 切出来的还是她的原话，顺序还是她说的顺序（先说的重要）。**她以后可以重排，那才是她的权力。**

## 三种模式（+ 一档自定义）

| 模式 | 缓冲圈 | 总库 | 她的表现 |
|---|---|---|---|
| **遗忘** | 90% / 70% | 默认开启，她够不着 | 会忘，想起来也补不满 |
| **伪遗忘** | **100%** | 默认开启 | 看起来忘了，一提示全回来（**她自己也以为忘了**） |
| **永不忘记** | 100% | **她能直接查** | 什么都不忘 |
| **自定义** | 每个圈单独调 | 自选 | 想怎么配怎么配 |

**总库默认始终开启**——这样三档随时能切，切过去也回得来。

## 怎么接 DeepSeek Harness（DSH）

记忆库自带一个 **stdio MCP 壳**：`mcp/server.mjs`。在 DSH 的 profile 里加一条 MCP 服务器：

```json
{ "command": "node", "args": ["D:/你的路径/环形的心/mcp/server.mjs"] }
```

重启会话后她手里会多四个工具：

| 工具 | 干什么 |
|---|---|
| `ring_remember` | 记一件事（她选位置、拆钩子） |
| `ring_recall` | 想起来（给提示词，能捞回多少看缓冲圈） |
| `ring_search` | 查原话 |
| `ring_overview` | 看自己现在记着什么 |

**没有删除工具** —— 铁律：她决定记什么，库决定什么时候忘。她不能删数据。

衰减不用她管：每次会话启动补跑一次；长驻会话每小时看一次表，贴着凌晨 4 点、一天最多跑一次，漏掉几天会按天补齐。

## 怎么接 QQ（OneBot）

QQ 侧走外部桥接 [qq-bridge](https://github.com/Derpyu520/qq-bridge)（OneBot v11 → DSH），记忆库以补丁形式接入：

```
QQ → SnowLuma → qq-bridge ─┬─ DSH agent → mcp-ring（她主动记 / 想起来）
                            └─ ring-ingest（自动入库：逐条原文进总库，合并落闲聊圈）
```

两条硬规矩：

1. **接库是启动前置**：QQ 连上时库也必须连上，接不上一直重试，每条消息进来都会再试。
2. **先总库后进圈**：任何消息先写总库（原始备份），再按她的表态进圈；她没表态的合并落闲聊圈，合并那条不重复写总库。

## 接别的框架（AstrBot / NapCat / 自己写的）

记忆库本体不认识任何框架。它只认两样东西：

```
MCP 四个工具    她主动记 / 想起来
一个 HTTP 接口   别人把聊天灌进来
```

`server/ingest-server.mjs` 就是那个 HTTP 接口 —— **谁的框架都行，POST 过来就能记，环心本体一行代码没改**：

```
QQ → AstrBot 插件 ──POST /ingest──► ingest-server ─┬─ vault   每条原文
                                                   └─ ring4   同一段对话合并成一条
```

```bash
node server/ingest-server.mjs        # 默认 127.0.0.1:5188
curl http://127.0.0.1:5188/health    # {"ok":true,"vault":0,...}
```

主人判定不靠框架的"管理员"概念（AstrBot 的 `admins_id` 是 WebUI 登录名，不是 QQ 号），
而是靠 `owners` 配置比 `uid`。配了之后总库里长这样：

```
2026/10/31 22:38｜私聊：【管理员】某人：今天中午吃的面不错
```

AstrBot 现成的转发插件在 [`integrations/astrbot/`](integrations/astrbot/)，三步装好。
换别的框架只要照着它的接口 POST 就行，见那份 README 的「接口」一节。

> **两条路互斥**：`qq-bridge` 和 `ingest-server` 别同时往同一个 `.db` 写，
> 否则同一句话会在总库里出现两次。要同时养两只机器人，就给它们两个库文件。

## 设计原则

1. **她决定，库执行**——判断权在人这边，遗忘权在库这边
2. **记忆是"点"，不是"一段话"**——所以能忘出碎片（"记得和谁，忘了干了什么"）
3. **原文是文件，索引只是缓存**——换检索方式不用迁移数据
4. **不张冠李戴**——只做"忘掉"，不做"记歪"
5. **零第三方运行时依赖**——Node 24 内置 `node:sqlite`，克隆下来就能跑
