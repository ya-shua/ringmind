# 环形的心 · Ringmind

**v1.3.5**

一个**会遗忘**的记忆库。

给 AI 角色用的记忆系统：**她决定记什么，库决定什么时候忘。**

---

## 怎么装

**要 Node.js 22.5 以上**（用了内置的 `node:sqlite`，不需要装任何依赖）。

```bash
git clone https://github.com/ya-shua/ringmind.git
cd ringmind
node src/web/server.js
```

Windows 上直接双击 **`启动面板.bat`** 也行；想让它缩在后台不占窗口，双击 **`后台启动.vbs`**。

第一次启动会在窗口里打印一串**访问令牌**，同时写进 `data/token.txt`。浏览器打开 <http://127.0.0.1:5173>，用这串令牌登录就行。

> 令牌只在第一次生成。忘了就去看 `data/token.txt`。

## 更新

面板**左下角**发现新版本会自己冒出一个框，点「更新」就行——它会拉最新代码、自动重启，然后页面自己刷新。

**记忆库、设置、令牌、OneBot 配置都不会动。** 这些东西不在代码里：
`data/`、`libraries.json`、`data-location.json`、`onebot.json` 全在 `.gitignore` 里，更新只换程序。

你要是改过代码，更新前它会先把你改动收进 `git stash`，不会硬盖掉。

git 协议被墙时自动改走 GitHub 源码包（只覆盖仓库跟踪的文件），版本号识别也一样准——更新完不会一直提示有新版本。

不想用面板更新就手动来：

```bash
git pull
```

然后重启面板。

## 为什么做这个

现在的 AI 记忆都是"数据库"：存进去，永远读得出来。

**那不是记忆，那是档案。**

人会忘。忘得越久越模糊，被提醒能想起来一些，**但想不全**。

> "被提醒了也想不全"——这才是人。

所以这套东西的核心不是"存得住"，是**"忘得像"**。

## 一条记忆的一生

```
① 发生    她决定：记不记？多重要？放哪一圈？哪些点最要紧？
     ↓
② 安家    进她自己选的那一圈
     ↓
③ 活着    被人提起 → 自动往回拉一点（无意识，她管不了）
     ↓
④ 淡去    时间到 或 那一圈满了 → 往外掉一圈，同时删掉一部分"点"
     ↓
⑤ 模糊    只剩钩子，提一句还能"啊对对对"
     ↓
⑥ 尽头    钩子也丢了 = 真的忘了
```

**关键：她有权选择记住什么，但无权决定忘记什么。**

### 「淡去」什么时候跑

没有独立的定时进程：**每次会话接入时检查一次，今天还没跑过就立刻补跑**，另加凌晨 4 点的兜底（只在有会话活着时才有效）。

- **一天最多跑一次**，按自然日算，不按"距上次满 24 小时"——后者会跟着接入时刻往后漂，漂过你常用的那个时间点就整天漏（出现过 11/5 20:57 → 11/7 23:24，漏了 50 小时）
- **一天没开对话，它就一天没跑**；下次接入会按缺的天数一次补齐（每缺一天多掉一圈，最多补 30 天）
- **掉线不影响**：它看的是"会话在不在"，不是网络通不通
- 跑之前先在 `.decay-state.json` 占住今天，两个会话同一秒起来也只有一个会真跑

面板「记忆更新」页有**更新日志**：每次真跑过都记一条，**包括跑了但一条都没动的那次**，并记下触发方式（会话启动补跑 / 凌晨兜底 / 手动点）。
只记"有变动"的那次，就分不出"没跑"和"跑了没动"——这是之前面板会误报"好久没跑"的原因。

## 九个位置

| 位置 | 装什么 | 停留 | 可配 |
|---|---|---|---|
| 数据总库 | 原始存档，**她访问不到** | 永久（可设条数） | ✅ |
| 自我圈（圆心） | 她自己钉住的秘密/底线/承诺 | 永不外出（上限 300） | ✅ |
| 一圈 | 极其强烈 | 180 天 | ✅ |
| 二圈 | 很开心 / 很难过 | 60 天 | ✅ |
| 三圈 | 有点意思 | 14 天 | ✅ |
| **闲聊圈（四圈）** | 日常 | 5 天（第 1 天 100%，每天 -5%，待满 80%） | ✅ |
| **模糊圈（五圈）** | 开始糊了 | 30 天（一进去就是 40%） | ✅ |
| 回忆圈 | 只剩 30% 的随机点，想不起来 | 一年后彻底消失 | ✅ |
| 缓冲圈 | 闲聊圈、模糊圈的备份，唯一能"想起来"的通道 | 跟主圈同步 | ✅ |

**她自己只知道四个位置**：自我圈（圆心）、一圈、二圈、三圈。

**闲聊圈（四圈）是接盘层**：她没表态、没记的事都自动落进那里（5 天逐日淡）——她不知道有这一格，也就不会去管理它。**模糊圈和回忆圈更不会告诉她**，那两个是她掉进去才会撞见的；她也不会发现自己掉进去了，只会觉得"这事我想不太起来了"。

**百分比全部以「原文」为标尺**，不是叠乘。

> 上表的停留天数是**没选预设时的兜底值**。实际用预设：一圈 90 天、二圈 30 天、三圈 10 天（三档预设的圈一二三都一样，差别在闲聊/模糊/回忆圈的容量）。

### 怎么说这些位置

**名字在前，圈号在后。** 说「闲聊圈（四圈）」，不要只说"圈四"，也不要只说"闲聊圈"。

**一圈、二圈、三圈不起别名** —— 数字本身就是顺序，叫"长久圈""近事圈"那种反而跟实际天数打架（模糊圈 30 天其实比闲聊圈 5 天长）。

**光给她一个整句、她自己没拆点的时候，库会按标点替她切。** 一个字都不改，也不替她总结 —— 切出来的还是她的原话，顺序还是她说的顺序（先说的重要）。**她以后可以重排，那才是她的权力。**

## 三种模式（+ 一档自定义）

| 模式 | 缓冲圈 | 总库 | 她的表现 |
|---|---|---|---|
| **遗忘** | 90% / 70% | 默认开启，她够不着 | 会忘，想起来也补不满 |
| **伪遗忘** | **100%** | 默认开启 | 看起来忘了，一提示全回来（**她自己也以为忘了**） |
| **永不忘记** | 100% | **她能直接查** | 什么都不忘 |
| **自定义** | 每个圈单独调 | 自选 | 想怎么配怎么配 |

**总库默认始终开启**——这样三档随时能切，切过去也回得来。

### 「可查询总库」这个开关

三档固定模式里，这一行**根本不出现** —— 那几档里她翻不到原始聊天记录，开关只是个标记，
所以干脆不给你点。真正接进检索的只有**「自定义」**模式。

而在自定义模式里打开它，会先弹一次确认：

> 开了之后，她能逐条翻回聊天的原始记录 —— 包括已经忘掉的。
> 这是整套里唯一能让她看见原文的开关。开着，「忘掉」就不再是忘掉了。

**关掉不用确认**，只有打开要过这一道。

### 总库有没有上限

有，只是**默认不限**。总库（vault）是原文存档，只增不减，机器跑几年会把磁盘吃满；
想设就设一条条数上限，超了删**最旧的**（删了真找不回来，所以默认不设）：

```bash
node scripts/set-vault-cap.mjs          # 看现在多少、用了多少
node scripts/set-vault-cap.mjs 200000   # 最多留 20 万条
node scripts/set-vault-cap.mjs 0        # 回到不限
```

这条上限每次写记忆时都会检查（`remember → trimVault`），改完立刻生效。

## 怎么接 DeepSeek Harness（DSH）

记忆库自带一个 **stdio MCP 壳**：`mcp/server.mjs`。在 DSH 的 profile 里加一条 MCP 服务器：

```json
{ "command": "node", "args": ["D:/你的路径/环形的心/mcp/server.mjs"] }
```

重启会话后她手里会多四个工具：

| 工具 | 干什么 |
|---|---|
| `ring_remember` | 记一件事（她选位置、拆钩子） |
| `ring_recall` | 想起来（给提示词，能捞回多少看缓冲圈） |
| `ring_search` | 查原话 |
| `ring_overview` | 看自己现在记着什么 |

**没有删除工具** —— 铁律：她决定记什么，库决定什么时候忘。她不能删数据。

衰减不用她管：每次会话启动补跑一次；长驻会话每小时看一次表，贴着凌晨 4 点、一天最多跑一次，漏掉几天会按天补齐。

## 怎么接 QQ（OneBot）

QQ 侧走外部桥接 [qq-bridge](https://github.com/Derpyu520/qq-bridge)（OneBot v11 → DSH），记忆库以补丁形式接入：

```
QQ → SnowLuma → qq-bridge ─┬─ DSH agent → mcp-ring（她主动记 / 想起来）
                            └─ ring-ingest（自动入库：逐条原文进总库，合并落闲聊圈）
```

两条硬规矩：

1. **接库是启动前置**：QQ 连上时库也必须连上，接不上一直重试，每条消息进来都会再试。
2. **先总库后进圈**：任何消息先写总库（原始备份），再按她的表态进圈；她没表态的合并落闲聊圈，合并那条不重复写总库。

## 把历史聊天导进来（QQ 导出）

上面那套是**从现在开始**记。以前的聊天记录想补进来，走面板里的**导入页**：

**侧边栏「其他」→「导入」**

### ① 环境

页顶一张环境卡：QCE 通不通、QQ 进程、令牌，一眼看清。没就绪时下方出安装清单
（下载安装 → 退出 QQ → 启动带注入的 QQ），做完自动检测推进。

### ② 导出到缓冲区

「选会话导出」标签页：选好友、选时间范围、点**「导出到缓冲区」**。
导出的文件先落进记忆库旁边的 `imports/` 文件夹（缓冲区），不直接进库——
什么时候导、导不导，都是你说了算。

### ③ 从缓冲区写进记忆库

「缓冲区」标签页：挑一份，定处理方式，确认**「她是谁」**（哪些 QQ 号说的话算她说的，
自动按会话对面预填），点**「写进记忆库」**。导错了从缓冲区删掉就行，已写进库的不受影响。

两种处理方式：

| 方式 | 做法 | 成本 |
|---|---|---|
| **人格筛选** | 她把整段对话读一遍，自己决定哪条留、进哪个圈 | 消耗 token，一次性（右侧「她的人格」卡配 API） |
| **全量计入** | 不读也不判断，按现有规则把每条消息都塞进圈 | 零成本 |

**私聊建议人格筛选，群聊建议全量计入。**

### 撤回与历史

「导入历史」标签页列出每一批导入，按批**撤回**——记忆、要点、总库原文一起清，
去重记录一并清掉，撤了能重导。群聊不能漫游拉取：在 QCE 界面里导出后，走「从 QCE 任务导入」收进来。

> 导出器是 [QQ Chat Exporter](https://github.com/shuakami/qq-chat-exporter)（NapCat 注入），
> 它只管把记录从 QQ 里倒出来，不参与记忆库的任何判断。装到 `vendor/`，`.gitignore` 里，
> 不算这个项目的一部分。

## 接别的框架（海螺 / AstrBot / NapCat / 自己写的）

记忆库本体不认识任何框架。它只认两样东西：

```
MCP 工具        她主动记 / 想起来        ← 海螺、任何 DSH agent
一个 HTTP 接口   别人把聊天灌进来        ← AstrBot、NapCat 直连、自研机器人
```

**每个框架一个薄适配器，只做三件事**：拿到文本 → 调上面的通用层 → 挂回它的回复对象。
合并、幂等、衰减这些全在通用层，适配器一行都不许有 —— 每加一个框架，只是加个几十行的文件。

现成的四份在 [`integrations/`](integrations/)：

| 框架 | 状态 | 走哪条路 |
| --- | --- | --- |
| [海螺（conch）](integrations/conch/) | ✅ 在用 | MCP `ring_ingest` |
| [SnowLuma + qq-bridge](integrations/qq-bridge/) | ✅ 在用 | 桥接不写记忆，只交出 MCP 工具 |
| [AstrBot](integrations/astrbot/) | 📦 示例 | HTTP `POST /ingest` |
| [NapCat（OneBot v11）](integrations/napcat/) | 📖 照着写 | HTTP `POST /ingest` |

`server/ingest-server.mjs` 就是那个 HTTP 接口 —— **谁的框架都行，POST 过来就能记，环心本体一行代码没改**：

```
QQ → 任何机器人 ──POST /ingest──► ingest-server ─┬─ vault   每条原文
                                                 └─ ring4   同一段对话合并成一条
```

```bash
node server/ingest-server.mjs        # 默认 127.0.0.1:5188
curl http://127.0.0.1:5188/health    # {"ok":true,"vault":0,...}
```

> 两条路（HTTP / MCP）的写入行为完全一致，同一份 `src/core/ingest.js`。
> 但**三条路别同时写同一个 `.db`**（qq-bridge / ingest-server / 海螺），否则同一句话会进去两遍。

### 合并规则：五条判据

同一段对话会合并成一条 `ring4`，不然闲聊几天就把库撑爆。

**规则只有一份**，在 `src/core/ingest.js` 的 `ingestMessage()` 里 —— HTTP 入口和 MCP 的
`ring_ingest` 都调它。以前只有 HTTP 那条路有合并，换个入口规则就丢了：语音合成一句话写一条，
一个晚上能灌进来几十条工具回执。

五条判据，**缺一条就不算同一段对话**：

| # | 判据 | 说明 |
|---|---|---|
| ① | 同一个聊天 | `private:1234` / `group:5678` 各自成段 |
| ② | 同一个发言方 | 她和别人分开算，不混进同一条 |
| ③ | 时间不回溯 | 补录历史时时间往回跳 → 宁可新开一条，否则顺序全乱 |
| ④ | 间隔 ≤ 90 秒 | `gapMs`：停了一会儿就是换话题了 |
| ⑤ | 本段 ≤ 5 分钟 | `mergeWindowMs`：从首句算，聊再久也不能无限长 |

只卡 ⑤ 的话，一小时里断断续续的闲聊会被拼成一大坨（实测单条最长 814 字）；
加上 ④，同一天最长降到 145 字。

④⑤ 都能改：`server/ingest.json` 里写 `gapMs` / `mergeWindowMs`，
或者用环境变量 `RING_GAP_MS` / `RING_MERGE_WINDOW_MS`。启动日志会打出实际生效的值。

> 合并游标存在库里（`conv_state` 表），不是进程内存 —— 重启、换入口都接得上同一段对话。

### 同一条消息只写一次

框架重连、重放、重试很常见，同一条消息会被 POST 两遍。带上 `message_id` 就只会写一次：

```json
{ "text": "面有点辣", "umo": "aiocqhttp:private:1234567890", "message_id": "7482103" }
```

库里按 `message_id` 做唯一索引（`NULL` 不算重复，所以她自己主动记的不受影响）。
**不做文本去重** —— 连发十次「在吗」是十件事，不是同一件。

### 语音消息怎么进库

语音转文字不可能 100% 准，所以转写**不冒充原话**：

```json
{
  "text": "[语音]",
  "note": "他说今天会下雨，就不出门了",
  "message_id": "7482104",
  "umo": "aiocqhttp:private:1234567890"
}
```

- `content` 留 `[语音]` —— 她记住的是"这里有人说了句话"
- 转写进 `note`，并标上 `note_suspect`（面板显示成"可能不准"）
- 转写错了也不会污染原话：原文那一格永远只有占位符

> `speaker` 传 `"self"` 表示"她自己说的"。这个值决定衰减速度：`self` 的话存活时间是别人的
> **3 倍**（`selfSpeechWeight`）。传成显示名就等于放弃这个待遇。

主人判定不靠框架的"管理员"概念（AstrBot 的 `admins_id` 是 WebUI 登录名，不是 QQ 号），
而是靠 `owners` 配置比 `uid`。配了之后总库里长这样：

```
2026/10/31 22:38｜私聊：【管理员】某人：今天中午吃的面不错
```

AstrBot 现成的转发插件在 [`integrations/astrbot/`](integrations/astrbot/)，三步装好。
换别的框架只要照着它的接口 POST 就行，见那份 README 的「接口」一节。

> **两条路互斥**：`qq-bridge` 和 `ingest-server` 别同时往同一个 `.db` 写，
> 否则同一句话会在总库里出现两次。要同时养两只机器人，就给它们两个库文件。

## 上传前的隐私门禁

仓库带一道门禁：**提交和推送时自动检查，防止把不该公开的东西带出去。**

```powershell
# 重新 clone 或换机器后跑一次（.git/hooks 不跟仓库走）
node scripts/install-git-hooks.mjs

# 手动查一遍全部
node scripts/privacy-gate.mjs --all
```

查两件事：

**① 隐私** —— 本机绝对路径、令牌、带 `qq`/`uin`/`账号` 上下文的号、手机号、真实邮箱。
**② 内部文档** —— `docs/`、`demo/`、`vendor/`、`backups/` 这些目录，以及「设计-」「交接」「遗留问题」这类过程性文档。

判成**拦截**的会真的挡下提交；判成**警告**的只提示（比如引号里的裸数字，可能是真号也可能只是测试数据）。

### 为什么不裸扫数字

「5-11 位数字」同时匹配真 QQ 号、端口、毫秒常量、字节数和测试假号。裸扫的结果是满屏误报，人很快就会养成「反正都是误报」的习惯直接跳过 —— 那门禁就废了。所以规则分三层：

- **拦截**：证据足够强，几乎不可能是正常代码
- **警告**：像，但可能只是示例数据，不拦
- **放过**：明确的正常写法（版本号、端口、毫秒、`1234567890` 这种占位号）

令牌的判定也收紧到「**既有数字、又同时有大写和小写**」—— 只看长度会把 `vaultAccessible`、`stopImmediatePropagation` 这些正常标识符全认成令牌。

### 误报了怎么办

在那一行加注释 `privacy-ok` 就跳过：

```js
const demo = "13800138000"; // privacy-ok 文档示例号
```

确实需要放行的常驻数字，加进 `scripts/privacy-gate.mjs` 的 `BENIGN_NUMBERS`。

### 兜底

`.github/workflows/privacy.yml` 在推送后还会再查一遍 —— 防的是 `.git/hooks` 丢了、或者有人 `git commit --no-verify` 绕过。
## 设计原则

1. **她决定，库执行**——判断权在人这边，遗忘权在库这边
2. **记忆是"点"，不是"一段话"**——所以能忘出碎片（"记得和谁，忘了干了什么"）
3. **原文是文件，索引只是缓存**——换检索方式不用迁移数据
4. **不张冠李戴**——只做"忘掉"，不做"记歪"
5. **零第三方运行时依赖**——Node 24 内置 `node:sqlite`，克隆下来就能跑

### v1.5.3 · 2026-11-09

**合并规则从"一个入口的私货"变成"所有入口共用一份"，并且同一条消息只写一次。**

起因：`声来说话` 那个插件一夜往闲聊圈灌了 54 条工具回执（每条都是「用音色 X 说了一句 Y」）。
根子在合并规则只写在 `server/ingest-server.mjs` 里 —— 换个入口（海螺走 MCP 的 `ring_ingest`）
规则就没了，一次调用写一条。

- 合并逻辑下沉到 `src/core/ingest.js` 的 `ingestMessage()`，HTTP 入口和 MCP `ring_ingest`
  共用。**五条判据一条没改**：同一聊天 / 同一发言方 / 时间不回溯 / 间隔 ≤ 90 秒 / 本段 ≤ 5 分钟。
- **合并游标搬进库**（`conv_state` 表）：原来放在进程内存里，重启（MCP 每次开会话都重起）
  就断了，同一段对话会被拆成两截。

### v1.5.2 · 2026-11-09

**记忆列表的最后一列换成「还能装」。**

- 原来那一列是「剩余」= 还看得见的点占原来的几成。它基本不动：闲聊圈 5 天只淡到 80%，而一条记忆通常只有 3 个点，`round(3 × 可见比例)` 在前几天全都取整回 3 —— 于是永远 100%，看着像坏了。这一列现在改成**这一圈的剩余容量**，按比例显示（`∞` = 不设上限），鼠标悬停能看到「装了 191 / 400 条，还能装 209 条（52%）」。
- 容量数据复用概览那次请求，不额外打接口；同一圈的行显示一样，因为那是圈的量，不是每条自己的。
